**Use-case Narrative**

**1\. Happy Path (Основной успешный сценарий)**

**Цель:** Получить готовый протокол встречи с выделенными решениями и задачами после загрузки аудиозаписи и слайдов.

|     |     |     |
| --- | --- | --- |
| Шаг | Действие Актора | Ответ Системы |
| 1   | Пользователь входит в систему и нажимает "Создать новый протокол". | Система открывает интерфейс загрузки файлов. |
| 2   | Пользователь загружает аудиофайл встречи (например, meeting_audio.mp3) и файл презентации (например, slides.pdf). | Система валидирует форматы файлов (.mp3, .wav, .pdf, .png) и отображает прогресс загрузки. |
| 3   | Пользователь нажимает кнопку "Начать обработку". | Система запускает конвейер обработки данных. |
| 4   | _(Шаги системы)_ | Система выполняет параллельно:  <br>1\. **Speech-to-Text:** Транскрибирует аудио в текст с временными метками.  <br>2\. **OCR:** Извлекает текст из загруженной презентации. |
| 5   | _(Шаги системы)_ | Система использует NLP-модели для анализа объединенного текста и:  <br>\- Выделяет ключевые темы обсуждения.  <br>\- Определяет и формулирует **решения**.  <br>\- Извлекает **action items** (задачи), назначает ответственных (на основе анализа речи, например, "Мария, пожалуйста, подготовь отчет") и предлагает дедлайны. |
| 6   | _(Шаги системы)_ | Система структурирует все данные в единый документ (протокол), включая:  <br>\- Краткую сводку.  <br>\- Детальную расшифровку с таймстемпами.  <br>\- Список решений.  <br>\- Список задач с ответственными и сроками.  <br>\- Текст, извлеченный из слайдов. |
| 7   | Система автоматически сохраняет протокол в истории встреч пользователя и уведомляет его о готовности. | Пользователь получает уведомление "Ваш протокол готов". |
| 8   | Пользователь просматривает готовый протокол, подтверждает его корректность. | Система предлагает опции: "Экспорт в DOCX/PDF", "Отправить на почту", "Создать задачи в Trello/Jira". |
| 9   | Пользователь выбирает "Создать задачи в Jira". | Система через API создает задачи в подключенной Jira, проставляет ответственных и дедлайны. |

**2\. Alternative Flows (Альтернативные сценарии)**

## UC1 — Авторизация
**Акторы:** Пользователь

**Предусловия:** Аккаунт существует; при необходимости подтверждён email.

**Основной сценарий (Happy Path):**
1. Пользователь открывает экран входа.
2. Вводит email и пароль.
3. Система валидирует формат и сверяет учётные данные.
4. При успехе выполняется вход и редирект на главный экран.

**Постусловия:** Пользователь авторизован.

**Ценность:** Быстрый и безопасный доступ к персональному функционалу.

**Альтернативные сценарии:**
- **A1. Неверные данные.** Сообщение: «Неверный email или пароль». Предлагается повторный ввод, восстановление пароля или регистрация.
- **A2. Включён MFA/2FA.** Запрос кода, подтверждение, завершение входа.

**Ошибки:**
- **E1. Сервис аутентификации недоступен.** Сообщение: «Сервис временно недоступен. Проверьте подключение и попробуйте снова». Кнопка «Повторить».

## UC2 — Загрузка материалов встречи
**Акторы:** Пользователь

**Предусловия:** Пользователь авторизован.

**Основной сценарий:**
1. Пользователь выбирает «Создать новый протокол».
2. Загружает аудио (MP3/WAV) и, при наличии, слайды (PDF/PPTX/PNG).
3. Система валидирует форматы/размеры, показывает прогресс и метаданные.
4. Пользователь подтверждает начало обработки.

**Постусловия:** Материалы приняты в обработку; создана запись встречи в истории.

**Ценность:** Простая точка входа в автоматизированный конвейер.

**Альтернативные сценарии:**
- **A1. Загружено только аудио.** Предупреждение и продолжение без раздела «Текст со слайдов».
- **A2. Онлайн‑запись вместо файлов.** «Начать запись онлайн»; доступ к микрофону/экрану; запись потока.

**Ошибки:**
- **E1. Неподдерживаемый формат/превышение лимита.** Чёткое сообщение, список поддерживаемых форматов/лимитов, рекомендации по сжатию/разделению.
- **E2. Разрыв соединения при загрузке.** Пауза, докачка с места обрыва.

---

## UC3 — Получение протокола встречи
**Акторы:** Пользователь

**Предусловия:** Материалы встречи загружены и обработаны (или идёт обработка).

**Основной сценарий:**
1. Система запускает конвейер: транскрибация аудио (с таймстемпами), OCR/извлечение текста со слайдов.
2. NLP‑анализ объединённого текста: темы, решения, action items (исполнители, сроки).
3. Формирование структурированного документа: сводка, детальная расшифровка, список решений, список задач, текст со слайдов.
4. Уведомление «Протокол готов»; пользователь открывает документ.
5. Пользователь просматривает/вносит пометки.

**Постусловия:** Готовый протокол сохранён в истории; доступен экспорт (UC4) и задачи (UC5).

**Ценность:** Экономия 1–2 часов ручной работы, полнота фиксации.

**Альтернативные сценарии:**
- **A1. Частичная обработка (низкое качество аудио).** Протокол с предупреждением и подсветкой низкой уверенности.

**Ошибки:**
- **E1. Сбой распознавания речи.** Остановка; рекомендации по улучшению записи/языку.
- **E2. Лимиты длительности/размера.** Блокировка старта с подсказками.
- **E3. Потеря сети.** Пауза и авто‑возобновление.

## UC4 — Экспорт протокола
**Акторы:** Пользователь

**Предусловия:** Протокол сформирован (UC3).

**Основной сценарий:**
1. Пользователь нажимает «Экспорт».
2. Выбирает формат (DOCX, PDF, Markdown) и опции (таймстемпы, слайды, приложения).
3. Система генерирует файл и предлагает скачать/отправить на email.

**Постусловия:** У пользователя есть внешний файл протокола.

**Ценность:** Удобное распространение и архивирование.

**Альтернативные сценарии:**
- **A1. Шаблоны экспорта.** Применение сохранённого шаблона стилей/структуры.

**Ошибки:**
- **E1. Ошибка генерации файла.** Сообщение, «Повторить», лог‑код для поддержки.

---

## UC5 — Формирование JSON файла с перечнем задач (и интеграция с Jira)
**Акторы:** Пользователь; Внешняя система Jira

**Предусловия:** Протокол сформирован; интеграция с Jira настроена (или будет настроена в процессе).

**Основной сценарий:**
1. Пользователь выбирает «Создать задачи» в карточке протокола.
2. Система формирует JSON action items (название, описание, исполнитель, дедлайн, ссылки, приоритет, метки).
3. Пользователь просматривает/редактирует черновик (массовое изменение проекта/исполнителя/сроков).
4. Выбор канала: скачать JSON или отправить в Jira по API.
5. При выборе Jira система создаёт задачи через API, ставит ответственных/сроки, возвращает ссылки.

**Постусловия:** Сформирован валидный JSON; при интеграции — задачи созданы и связаны с протоколом.

**Ценность:** Быстрый переход от обсуждения к исполнению.

**Альтернативные сценарии:**
- **A1. Интеграция не настроена.** Мастер подключения Jira; можно временно скачать JSON.
- **A2. Кастомный маппинг полей.** Редактор сопоставлений + сохранение шаблона.

**Ошибки:**
- **E1. Ошибка аутентификации/авторизации в Jira.** Сообщение и переподключение.
- **E2. Некорректный JSON/валидация схемы.** Подсветка полей, автоисправление типичных ошибок.
- **E3. Сбой сети/таймаут API.** Ретрай, частичная выгрузка помечается статусами.

## UC6 — Управление пользователями (Администрирование)
**Акторы:** Администратор

**Предусловия:** Администратор авторизован и имеет права.

**Основной сценарий:**
1. Администратор открывает консоль администрирования.
2. Просматривает список пользователей, статусы, роли, квоты.
3. Создаёт/блокирует/разблокирует пользователя, назначает роли, сбрасывает пароль, приглашает по email.
4. Сохраняет изменения; система фиксирует аудит‑лог.

**Постусловия:** Актуальное состояние базы пользователей; изменения зааудированы.

**Ценность:** Контроль доступа и безопасности.

**Альтернативные сценарии:**
- **A1. Массовые операции (CSV/SCIM).** Импорт/экспорт пользователей с валидацией.

**Ошибки:**
- **E1. Недостаточно прав.** Сообщение; рекомендация обратиться к супер‑админу.
- **E2. Конфликт данных (дубликат email).** Подсветка записи, инструкция по объединению/удалению.

## UC7 — Мониторинг работы системы (Администрирование)
**Акторы:** Администратор

**Предусловия:** Администратор авторизован.

**Основной сценарий:**
1. Администратор открывает «Мониторинг».
2. Просматривает метрики: очереди, времена, успешность стадий (STT/OCR/NLP), ресурсы, ошибки.
3. Фильтрует по периоду/типу задачи, проваливается в лог сессии.
4. По необходимости — перезапуск/приоритизация обработки.

**Постусловия:** Поддержана стабильность и SLA.

**Ценность:** Прозрачность и управляемость сервисом.

**Альтернативные сценарии:**
- **A1. Алёрты.** Пороговые уведомления в Slack/Email при отклонениях.

**Ошибки:**
- **E1. Модуль метрик недоступен.** Сообщение; деградация на базовый лог и экспорт.

## UC8 — Настройка системы (Администрирование)
**Акторы:** Администратор

**Предусловия:** Администратор авторизован; есть права на конфигурацию.

**Основной сценарий:**
1. Администратор открывает «Настройки».
2. Конфигурирует политики безопасности (MFA, пароль, SSO), лимиты (длительность аудио, размер файлов), очереди, языковые модели, регионы хранения данных.
3. Настраивает интеграции по умолчанию (Jira проекты/темплейты), шаблоны экспортов.
4. Сохраняет изменения; система валидирует и применяет без даунтайма (где возможно).

**Постусловия:** Параметры обновлены; изменения задокументированы в аудит‑логе.

**Ценность:** Управление политиками, производительностью и совместимостью.

**Альтернативные сценарии:**
- **A1. Черновики конфигураций и откат.** Сравнение версий и rollback.

**Ошибки:**
- **E1. Некорректные значения.** Подсказки по диапазонам/форматам; запрет сохранения до исправления.
- **E2. Конфликт настроек.** Предупреждение и подтверждение.

## UC9 — Регистрация
**Акторы:** Пользователь

**Предусловия:** Пользователь ещё не зарегистрирован.

**Основной сценарий:**
1. Пользователь открывает экран регистрации.
2. Вводит email, пароль, имя.
3. Система валидирует формат email, сложность пароля, уникальность email.
4. Система создаёт учётную запись.
5. Система автоматически авторизует пользователя и перенаправляет на главный экран.

**Постусловия:** Создан и активирован новый аккаунт; пользователь авторизован.

**Ценность:** Быстрый и безопасный старт работы.

**Альтернативные сценарии:**
- **A1. Некорректные данные.** Подсветка полей, подсказки, повторный ввод.

**Ошибки:**
- **E1. Внутренняя ошибка.** «Внутренняя ошибка сервера. Попробуйте ещё раз». Данные формы сохраняются локально.
- **E2. Email уже используется.** «Пользователь с таким email уже зарегистрирован». Варианты: вход или восстановление пароля.

## UC10 — Просмотр истории
**Акторы:** Пользователь

**Предусловия:** Пользователь авторизован; есть сохранённые встречи/протоколы.

**Основной сценарий:**
1. Пользователь открывает «Историю встреч».
2. Система загружает упорядоченный список (дата, название, участники, теги, статус).
3. Пользователь применяет фильтры/поиск.
4. Открывает выбранную запись/протокол.

**Постусловия:** Пользователь ознакомился с материалами прошлых встреч.

**Ценность:** Быстрый поиск и повторное использование знаний.

**Альтернативные сценарии:**
- **A1. История пуста.** CTA «Создать новый протокол» (переход к UC2).

**Ошибки:**
- **E1. Не удалось загрузить историю.** Сообщение + «Повторить»; отображение кэша при наличии.

## UC11 — Просмотр профиля
**Акторы:** Пользователь

**Предусловия:** Пользователь авторизован.

**Основной сценарий:**
1. Пользователь открывает «Профиль».
2. Система отображает данные (имя, email), настройки (язык, TZ), интеграции (Jira), лимиты тарифа.
3. Пользователь при необходимости переходит к редактированию (UC12) или смене пароля (UC13).

**Постусловия:** Пользователь ознакомился с текущими данными и настройками.

**Ценность:** Прозрачность состояния аккаунта и интеграций.

**Ошибки:**
- **E1. Ошибка загрузки профиля.** Сообщение; «Повторить»; offline‑кэш.

## UC12 — Редактирование профиля
**Акторы:** Пользователь

**Предусловия:** Пользователь авторизован.

**Основной сценарий:**
1. Открывает «Редактировать профиль».
2. Изменяет имя, аватар, язык/локаль, часовой пояс, формат даты/времени.
3. (Опц.) Настраивает интеграции: Jira (URL, проект, OAuth/токен), шаблоны задач.
4. Система валидирует поля, предупреждает о рисках (влияние на шаблоны/экспорт).
5. Сохраняет изменения и сообщает «Данные успешно обновлены».

**Постусловия:** Данные и предпочтения обновлены; влияют на протоколы/экспорты.

**Ценность:** Персонализация и релевантность.

**Альтернативные сценарии:**
- **A1. Некорректные данные (символы/URL).** Подсветка поля и подсказка.

**Ошибки:**
- **E1. Ошибка синхронизации.** «Изменения не сохранены. Проверьте подключение». Локальный черновик и авто‑отправка позже.

## UC13 — Смена пароля
**Акторы:** Пользователь

**Предусловия:** Пользователь авторизован (или проходит восстановление по email).

**Основной сценарий:**
1. Открывает «Сменить пароль».
2. Вводит текущий пароль, новый пароль, подтверждение.
3. Система проверяет текущий пароль и политику сложности.
4. Сохраняет новый пароль, инвалидирует активные сессии (по политике) и сообщает «Пароль обновлён».

**Постусловия:** Пароль изменён; безопасность усилена.

**Ценность:** Контроль безопасности аккаунта.

**Альтернативные сценарии:**
- **A1. Забытый текущий пароль.** Запуск восстановления по email/SSO.

**Ошибки:**
- **E1. Неверный текущий пароль.** Сообщение; лимит попыток; защита от брутфорса.

---

## UC14 — Просмотр краткой истории предыдущих запросов
**Акторы:** Пользователь

**Предусловия:** Пользователь авторизован; система хранит быстрый лог последних действий.

**Основной сценарий:**
1. Пользователь открывает виджет «Недавние запросы».
2. Система показывает 5–10 последних операций (загрузка, обработка, экспорт) со статусами.
3. Быстрый переход к нужной встрече/протоколу.

**Постусловия:** Быстрый доступ к недавним действиям.

**Ценность:** Экономия времени при повторном доступе.

**Альтернативные сценарии:**
- **A1. Лента пуста.** Пояснение и CTA «Создать новый протокол».

**Ошибки:**
- **E1. Временная недоступность ленты.** Показ кэша/скелетона; кнопка «Обновить».

**3\. Error Handling (Обработка ошибок)**

|     |     |     |     |
| --- | --- | --- | --- |
| Ошибка | Причина | Действие Системы | Сообщение Пользователю |
| **1\. Сбой распознавания речи** | Аудиофайл поврежден, тишина, неизвестный язык. | Прекращает обработку, откатывает операции. | "Речь на аудио не распознана. Проверьте качество записи и язык обсуждения." |
| **2\. Плохое качество аудио** | Сильный шум, низкая громкость, множественные голоса. | Выполняет транскрипцию с пониженной точностью. В протоколе добавляется пометка **\[ВНИМАНИЕ: Качество аудио низкое. Текст может содержать ошибки\]** и выделяет фрагменты с низкой уверенностью распознавания. | "Аудио обработано с пометкой о низком качестве. Рекомендуем проверить ключевые решения и задачи." |
| **3\. Превышение лимита** | Длительность аудио > 2 часов или размер файла > 500 МБ. | Блокирует начало обработки. | "Превышен лимит длительности (2ч) или размера файла (500МБ). Пожалуйста, разделите встречу на части или используйте запись короче." |
| **4\. Неподдерживаемый формат файла** | Загружен файл с расширением .exe, .zip и т.д. | Немедленно отклоняет файл. | "Формат файла '.zip' не поддерживается. Пожалуйста, загрузите аудио (MP3, WAV) или документы (PDF, PNG, PPTX)." |
| **5\. Отсутствие интернет-соединения** | Разрыв соединения во время загрузки или обработки. | Приостанавливает операцию, сохраняет прогресс. Автоматически возобновляет с момента остатка при появлении сети. | "Соединение прервано. Обработка приостановлена. Повторное подключение..." |

**4\. User Value (Ценность для пользователя)**

1.  **Экономия времени:** Полная автоматизация рутинной работы по ведению и оформлению протоколов. Пользователь получает готовый документ за 5 минут вместо 1-2 часов ручной работы.
2.  **Снижение риска потери информации:** ИИ-ассистент фиксирует все детали встречи, которые человек может упустить из-за усталости или необходимости участвовать в дискуссии. Структурирование информации минимизирует риски недопонимания.
3.  **Повышение продуктивности и accountability:** Автоматическое извлечение задач и их интеграция в таск-менеджеры гарантирует, что ни одно поручение не будет забыто, и у каждого участника есть четкий список действий. Это ускоряет выполнение работ после встречи.
